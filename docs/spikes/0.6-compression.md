# Spike 0.6 — Compression

**Question (ADR-007):** does a trained zstd dictionary deliver 4–6× on short chat messages?
**Status:** ✅ **Passed, but the ADR as written was wrong.** The target is reachable only with a
design change.
**Code:** `spikes/compression/`
**Date:** 2026-09-01

---

## Method

8,000 synthetic conversational messages (short informal lines, code snippets, links, emoji, with
the heavy vocabulary reuse real chat shows). Average 36.7 bytes. Trained a zstd dictionary on
60%, measured on the held-out 40% — training and measuring on the same data would inflate the
result. Every configuration is round-trip verified, not just size-measured.

## Results

| Configuration | Ratio |
| :--- | ---: |
| Per-message, standard frame, with dictionary | **1.57×** |
| Per-message, magicless frame (no magic/checksum/dictID) | **2.38×** |
| Block of 8 messages | 3.92× |
| Block of 32 messages | 4.70× |
| **Block of 128 messages** | **5.32×** |
| Block of 512 messages | 5.95× |
| Block of 32, *no dictionary* | 1.92× |
| Block of 128, *no dictionary* | 3.41× |

Per-message framing overhead: **13 bytes standard, 5 bytes magicless** — against a 36.7-byte
average message.

Read-path cost (decompress a block, extract one message):

| Block size | Time |
| :--- | ---: |
| 32 | 0.6 µs |
| 128 | **2.2 µs** |
| 512 | 7.0 µs |

## Finding

**ADR-007's 4–6× claim is achievable, but not the way the ADR implied.** The architecture
described per-message compression (`body BLOB` per row in `ARCHITECTURE.md` §8.2). Measured
per-message, that gives **1.57×** — far short of target.

The cause is not the dictionary; it is fixed framing cost. zstd writes a 13-byte frame header
per compressed unit, which against a 36.7-byte payload is 35% overhead before any data is
encoded. Stripping the frame to magicless gets to 2.38×, and the residual payload analysis shows
3.53× would be the ceiling even with free framing.

Only **amortising the frame across many messages** reaches the target. At 128 messages per block
the ratio is 5.32× and a single-message read costs 2.2 µs — negligible, and in practice one
decompression serves the whole visible screen.

The dictionary is still doing real work: at a 128-message block it contributes 5.32× versus
3.41× without one, a 56% improvement.

## Consequences

- **ADR-007 revised** to specify block segmentation rather than per-message compression.
- **`ARCHITECTURE.md` §8.2 schema revised**: messages are stored in sealed segments of ~128,
  with recent messages held individually (magicless, 2.38×) until a segment fills.
- **Magicless framing is mandatory** wherever a message is compressed individually — it is a free
  8 bytes per message.
- Dictionary versioning must ship from the first release, as ADR-007 already noted.

## Caveats

The corpus is synthetic. Real chat has more vocabulary diversity, so expect the true ratio to be
somewhat lower — the *relative* ordering of the configurations is the durable finding, not the
absolute numbers. Re-run against a real corpus once dogfooding produces one.
